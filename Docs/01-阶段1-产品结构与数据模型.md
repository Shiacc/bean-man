## 2. 产品结构（分层与模块边界）

```
┌──────────────────────────────────────────────────────────┐
│ Views (SwiftUI)        只做渲染与手势，不含业务判断        │
├──────────────────────────────────────────────────────────┤
│ ViewModels (@Observable)  持有页面状态、编排 Service 调用  │
│                          全部 @MainActor                  │
├──────────────────────────────────────────────────────────┤
│ Services (无状态 / 纯函数)  算法、队列、导入导出、统计、TTS │
│                          输入输出只用值类型 DTO，可单测     │
├──────────────────────────────────────────────────────────┤
│ Persistence (SwiftData)  @Model + Repository（唯一写入口） │
└──────────────────────────────────────────────────────────┘
```

三条硬规则，后面每个阶段都据此审查：

1. **View 不出现 `try? context.save()`**，只有 Repository / ViewModel 能写库。
2. **算法与导入不依赖 SwiftData**：`SRSAlgorithm.schedule(state:rating:now:calendar:)` 的入参出参都是 struct，测试里不需要建 ModelContainer。
3. **一个 View 一个 ViewModel**，ViewModel 超过 250 行就拆 Service。

Repository 层是本设计新增的一层（原提示词只有 Service），理由：SwiftData 的 `@Query` 无法覆盖「按到期日 + 上限 + 排除已学新词」这种组合查询，必须用显式 `FetchDescriptor`；把这类查询集中到 `StudyRepository` 才能被单测覆盖。

### 4.3 七个关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| M1 | `Word.uniqueKey = "<deckID>\|<normalized>"` 配 `.unique` | SwiftData 不支持复合唯一约束，但可以用「派生唯一键」在**数据库层**保证同库不重词，导入时靠它判冲突，不靠内存遍历 |
| M2 | `Word.deckID`、`ReviewState.deckID` 反规范化 | iOS 17 的 `#Predicate` 对可选关系链（`$0.deck?.id == x`）不稳定，踩过会随机崩；存 UUID 后谓词退化为简单相等 |
| M3 | 新词 = `reviewState == nil`，首次评分时才创建 ReviewState | 避免为 0 次学习的词预生成 5000 条状态；「新词」判定变成一次可选关系判空 |
| M4 | `StudyRecord` 随 Word 级联删除，`StudySession` 独立存活 | 删除词库后明细清干净（无孤儿），但累计数/正确率/连续打卡/7 日图仍在，统计不会「归零」 |
| M5 | 会话存 `dayKey` 字符串 | 连续打卡与柱状图只需 `dayKey` 集合运算，不反复用 Calendar 重算，跨时区/夏令时不会算错一天 |
| M6 | 设置用 `key = "app"` 单例行 | SwiftData 没有「单例」概念，哨兵键 + 唯一约束保证读到的永远是一条；缺失时 Repository 自动补建 |
| M7 | `tags` 用 `tagsRaw` 存储 + 计算属性 | SwiftData 存 `[String]` 走 transformable，CSV 导出会变成不可控二进制；逗号串保证导入导出往返一致 |

### 4.4 索引与查询模式

SwiftData 的 `#Index` 在 iOS 18 才有，iOS 17 上靠「谓词简单 + 复合字段」保性能。三条核心查询：

```swift
// 1) 到期复习（全库，跨词库）
let cutoff = calendar.startOfDay(for: now)
FetchDescriptor<ReviewState>(
    predicate: #Predicate { $0.dueDate <= cutoff && $0.isSuspended == false },
    sortBy: [SortDescriptor(\.dueDate), SortDescriptor(\.lapses, order: .reverse)]
)

// 2) 今日已学新词数（额度扣减依据）
FetchDescriptor<StudyRecord>(
    predicate: #Predicate { $0.wasNew && $0.reviewedAt >= todayStart }
)

// 3) 全部新词（无状态），按词库与顺序
FetchDescriptor<Word>(
    predicate: #Predicate { $0.reviewState == nil && $0.deckID == deckID },
    sortBy: [SortDescriptor(\.sortIndex)]
)
```

### 4.5 迁移策略

从第一天就建 `SchemaV1` 与 `SchemaMigrationPlan` 骨架，后续加字段只写 lightweight 迁移，**绝不删库重建**：

```swift
enum BeanManSchemaV1: VersionedSchema {
    static var versionIdentifier = Schema.Version(1, 0, 0)
    static var models: [any PersistentModel.Type] {
```

## 5. 复习算法契约（简化 SM-2）

纯函数，唯一入参时钟，便于测试：

```swift
struct SRSInput: Sendable {
    var easeFactor: Double = 2.5
    var intervalDays: Int = 0
    var repetitions: Int = 0
    var lapses: Int = 0
    var phase: CardPhase = .new
}

enum SRSAlgorithm {
    static let minEase = 1.3
    static let maxEase = 3.0
    static let maxIntervalDays = 365

    static func schedule(_ input: SRSInput,
                         rating: Rating,
                         now: Date,
                         calendar: Calendar) -> SRSOutput
}
```

| 评分 | repetitions | intervalDays | easeFactor | phase |
|---|---|---|---|---|
| Again (1) | → 0 | → 1 | `max(1.3, e − 0.20)` | relearning，`lapses += 1` |
| Hard (3) | +1 | `reps==0 → 1`；`reps==1 → 2`；否则 `max(i+1, round(i×1.2))` | `max(1.3, e − 0.15)` | review |
| Good (4) | +1 | `reps==0 → 1`；`reps==1 → 3`；否则 `round(i×e)` | 不变 | review |
| Easy (5) | +1 | `reps==0 → 4`；`reps==1 → 7`；否则 `round(i×e×1.3)` | `min(3.0, e + 0.15)` | review |

- `dueDate = calendar.date(byAdding: .day, value: interval, to: calendar.startOfDay(for: now))`
- `intervalDays` 夹在 `1...365`；`easeFactor` 夹在 `1.3...3.0`
- 全部日期用 `Calendar.current`（含用户时区），**禁止** `TimeInterval(86400)` 硬算天
- Again 的 `dueDate` 定义为「明天 00:00」，因此同一天内不会立刻再出同一张卡（MVP 不做日内重排）

## 6. 今日队列契约

```swift
struct PlanQuota: Sendable {          // 已扣减今日已用额度后的剩余额度
    var remainingNew: Int
    var remainingReview: Int
}

enum DueQueueBuilder {
    static func build(due: [ReviewState], newWords: [Word],
                      quota: PlanQuota, limit: Int) -> [QueueItem]
}
```

规则（对应 D2）：

1. 复习 = `dueDate <= 今日 00:00` 且未挂起，按 `dueDate` 升序、`lapses` 降序，截断到 `remainingReview`。
2. 新词 = `reviewState == nil`，按 `sortIndex`，截断到 `remainingNew`。
3. 最终顺序：复习在前、新词在后；总数截断到 `dailyNewLimit + dailyReviewLimit` 的剩余部分。
4. 空队列 → 今日页显示小豆空状态，不显示「开始学习」。

| meaning | 释义、意思、中文 |
| example | 例句 |
| exampleTranslation | 例句翻译、例句释义 |
| tags | 标签 |
| note | 备注、笔记 |

解析器要求：UTF-8 带 BOM、CRLF、字段内逗号与换行（双引号包裹）、`""` 转义。校验：`word` 与 `meaning` 非空，否则该行跳过并记 `ImportIssue(row:reason:)`，**不整体失败**。

### JSON 备份

```json
{ "schemaVersion": 1, "exportedAt": "2026-11-07T12:00:00Z",
  "deck": { "name": "示例词库", "summary": "", "isBuiltIn": false },
  "words": [ { "word": "abandon", "phonetic": "/əˈbændən/", "partOfSpeech": "v.",
               "meaning": "放弃；抛弃", "example": "He abandoned the plan.",
               "exampleTranslation": "他放弃了这个计划。", "tags": ["CET4"], "note": "" } ] }
```

导入冲突策略由用户选：**跳过重复 / 覆盖释义 / 全部新建到新词库**。默认「跳过重复」。

## 11. 已识别风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| Swift 6 严格并发 × SwiftData | `@Model` 非 Sendable，跨 actor 传对象编译失败 | 模型只在 `@MainActor` 用；批量导入用 `@ModelActor`，跨层只传 `UUID` 与 DTO（见 D1） |
| iOS 17 `#Predicate` 可选关系不稳 | 运行期崩溃或查不到数据 | 反规范化 `deckID` / `wordID`（M2），谓词只做相等与日期比较 |
| 批量导入卡主线程 | 1000 行导入界面冻结 | `@ModelActor` 后台 context + 分批 200 条 save + 进度回调 |
| `@Query` 不随批量写自动刷新 | 导入后列表空白 | 导入完成发 `NotificationCenter` 事件，ViewModel 重新 `fetch` |
| 关系数组无序 | 词条顺序跳动 | 显式 `sortIndex`，所有列表按它排序 |
| 通知重复/漏发 | 改时间后收到两条 | 固定 `identifier = "daily.reminder"`，先 `removePendingNotificationRequests` 再 `add` |
| TTS 无声音（静音键） | 用户以为坏了 | 用 `.playback` category + `AVAudioSession.setActive`，并在设置页说明 |
