## 1. 产品定位

### 1.1 一句话

一个**离线优先、无账号、打开即背**的单词卡 App：每天只问你要两样东西——今天的新词、今天到期的复习，用四档反馈把它们处理完。

### 1.2 问题与洞察

| 现状痛点 | 用户原话（访谈归因） | 我们的取舍 |
|---|---|---|
| 一进来就要登录、选词书、做测试 | 「我就想背两个词，为什么要先注册」 | 首启 3 步内进入第一张卡，示例词库开箱可用 |
| 词库动辄上万词，天天被「还剩 9800 个」追着跑 | 「看着那个数字就不想打开」 | 只显示**今天**的任务数，总数放统计页 |
| 打卡断一天就全盘崩 | 「断了一天就再也不想开了」 | 连续打卡只作为鼓励，断签不惩罚、不红字 |
| 广告和推送轰炸 | — | 无广告、无账号、无网络请求 |
| 复习算法看不懂 | 「为什么明天又要背」 | 每次评分后可以知道「几天后再见」 |

**核心洞察**：背单词的敌人不是难度，是**启动成本**。产品所有设计优先降低「打开 → 做第一张卡」的摩擦。

### 1.3 目标 / 非目标

**目标**

1. 首次打开到第一张卡 ≤ 60 秒（含引导）。
2. 单次学习 3–10 分钟内可完成，任何时刻可退出且不丢进度。
3. 完全离线可用；断网、飞行模式与联网无差别。
4. 复习安排可解释：用户能看懂「为什么今天有这个字」。

**非目标（v1 明确不做）**

- 不做账号、云同步、社交、排行榜、学习小组。
- 不做在线词库商店、不做版权词库（内置仅 24 个自写示例词）。
- 不做 OCR 取词、拍照查词、整篇文章精读。
- 不做 AI 生成例句（离线优先，且成本/延迟不可控）。
- 不做 Apple Watch / 小组件 / iCloud（列为 P2，视 v1 数据再定）。

### 1.4 成功指标（上架后 4 周观察）

| 指标 | 定义 | 目标 |
|---|---|---|
| 激活率 | 首次打开后 24h 内完成 ≥1 次学习（≥10 张卡） | ≥ 70% |
| 次留 | D1 回访 | ≥ 40% |
| 7 留 | D7 回访 | ≥ 25% |
| 周学习天数 | 人均每周有学习记录的天数 | ≥ 4 天 |
| 单次时长 | 一次会话中位数 | 5–9 分钟 |
| 导入使用率 | 使用过 CSV/JSON 导入的用户 | ≥ 30%（说明词库自建是刚需） |
| 崩溃率 | 会话崩溃比 | < 0.3% |

> 说明：v1 不做任何网络上报（见 §10），以上指标靠 App Store Connect 的聚合数据 + 用户主动导出的本地统计评估。

## 2. 用户与场景

### 2.1 用户画像

| 画像 | 特征 | 对设计的要求 |
|---|---|---|
| A. 备考学生（18–24） | 四六级/考研/雅思，有明确日期压力，词量大 | 每日新词可调高、支持大批量导入、进度可见 |
| B. 职场提升（25–35） | 碎片时间，通勤/午休，容易中断 | 单次时长短、强制保存、随时退出 |
| C. 兴趣自学（30+） | 无考试压力，怕被绑架 | 不想被催、可以完全静音、无红点 |

### 2.2 关键场景

| # | 场景 | 时长 | 设计响应 |
|---|---|---|---|
| S1 | 早高峰地铁，单手，可能无网 | 5–8 min | 竖屏单列、大按钮、底部四档、全离线 |
| S2 | 睡前躺着，屏幕暗 | 10 min | 深色模式、自动朗读可关、不刺眼 |
| S3 | 考前突击，一天想刷 200 个 | 30+ min | 复习上限可调到 500，队列自动分批 |
| S4 | 等电梯的 40 秒 | <1 min | 打开即今日页，一次点击进卡；退出不丢分 |

### 2.3 关键旅程（首次使用）

```
安装 → 引导（3 步，约 40s）→ 今日页（示例词库已就绪）
   → 点「开始学习」→ 引导提示「点卡片翻面」→ 翻面 → 四档评分
   → 第 2 张自动发音 → 完成 20 张 → 完成页（正确率/用时/连续 1 天）
   → 回到今日页，任务卡变为「今天的词过完了」
```

## 5. 功能规格

> 统一模板：**目的 → 入口 → 界面元素 → 规则 → 边界与异常 → 验收**。
> 所有文案遵循 §8.3 语气规范；所有动画时值见 §8.1。

### 5.1 F1 首次引导

**目的**：60 秒内完成「每日计划 + 提醒 + 词库」三件事，进入第一张卡。

**流程（4 步，可回退）**

| 步 | 标题 | 内容 | 可跳过 |
|---|---|---|---|
| 1 | 欢迎 | 一句话定位 + 橘子立绘；按钮「开始」 | 否（可关） |
| 2 | 每天背多少 | 新词 10 / 20 / 30 / 自定义（1–100，默认 20）；复习上限 20 / 50 / 100 / 200 / 自定义（1–500，默认 100） | 否（有默认值，可直接下一步） |
| 3 | 什么时候提醒 | 开关（默认开）+ 时间（默认 20:00） | 是（跳过则关闭提醒） |
| 4 | 用哪个词库 | 「用示例词库（24 词）」/「稍后导入」 | 否（二选一） |

**规则**

- 面板用底部 sheet 或全屏卡片；每步一个主按钮，左上「返回」，最后一步按钮文案「开始学习」。
- 选择「稍后导入」时，自动安装示例词库，保证今日页不为空。
- 完成后写 `AppSettings.onboardingCompleted = true`、`selectedDeckID`；幂等，不会重复执行。
- 通知授权在**第 3 步点「下一步」时**请求（不在启动时弹），被拒则第 3 步内联提示「已关闭，可稍后在设置开启」，不阻断流程。

**边界**

- 用户中途杀进程：下次启动重新走引导（不记录中间态）。
- 自定义输入非法（0、负数、非数字）：按钮禁用 + 行内提示。

**验收**：AC-01 ~ AC-05。

### 5.2 F2 今日页

**目的**：一眼看清「今天要干什么」，一次点击开始。

**界面元素（自上而下）**

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 头部 | 「今日」+ `M 月 d 日 · EEE` | `Date` |
| 小豆气泡 | 橘子立绘 + 一句话 + 副句 | `XiaodouMoment` |
| 任务卡 | `12 个待复习` `20 个新词`、进度条、`今日进度 8 / 40`、主按钮 | `TodayCounts` |
| 三连统计 | 今日已学 / 正确率 / 连续打卡 | `TodayViewModel` |
| 快捷行 | 「再复习 5 个错词」；当前词库名 + 词数 | `Deck` |

**文案随状态变化**

| 状态 | 气泡 | 主按钮 |
|---|---|---|
| 有待复习或有新词 | 「12 个到期词，先清一波？」+「先清到期，再学 20 个新词」 | 开始学习 |
| 全部完成 | 「今天的词过完了，连续打卡 7 天」 | 复习错词 |
| 无词库 | 「还没有词库，先导入一个吧」 | 导入词库（跳词库页） |

**规则**

- 进度条 = `learnedToday / (learnedToday + due + new)`，分母为 0 时显示 0 且不可点。
- 点击主按钮 → 全屏 P-02，**每次点击都重新构建队列**（保证跨天正确）。
- 从学习页返回后立即 `refresh`（今日计数、连续打卡可能已变）。
- 下拉刷新：手动重算（无网络请求，仅重算队列与计数）。

**边界**

- 跨夜停留在今日页：进入前台（`scenePhase == .active`）时重算一次，日期变化则刷新。
- 连续打卡断签：气泡文案改为鼓励语，不出现红字或负反馈。

**验收**：AC-06 ~ AC-10。

### 5.3 F3 学习会话

**目的**：把今天的队列处理完，每张卡一次回忆、一次诚实反馈。

**状态机**

```
idle → building（构队列，<50ms）→ front（正面）
front --翻面--> back --四档--> (还有卡) front（下一张，自动发音）
                          └→ (队列空) summary
任意状态 --关闭--> 退出（已评分的不丢）
```

**卡片正面**：单词（34pt 粗）、音标、喇叭按钮（朗读），底部提示「点击卡片查看释义」。
**卡片背面**：单词 + 音标 + 喇叭、词性胶囊、释义（26pt）、分隔线、「例句 / 例句翻译」、可选「备注」。
**翻面**：3D 翻转 0.42s（`rotation3DEffect` ±90°）。点卡片任意处、或点「显示答案」均可翻面。

#### 5.3.1 手势规范（F17）

**原则**：一个手势只做一件事；手势作用于「卡片区」，不劫持页面滚动与按钮。

| 手势 | 作用区 | 行为 | 触觉 | 可撤销 |
|---|---|---|---|---|
| 轻点 | 卡片 | 未翻面 → 翻面；已翻面 → 下一张（**跳过**，不评分、不写记录） | `.light` | — |
| 上滑 | 卡片 | 跳过当前这张（与「轻点已翻面」等效），不评分、不写记录 | `.light` | — |
| 左滑 | 卡片 | 判定「不认识」（Rating 1），卡片左移，右侧露出 dangerTint 动作层 | `.rigid` | 2 秒内可撤销 |
| 右滑 | 卡片 | 判定「认识」（Rating 4），卡片右移，左侧露出 successTint 动作层 | `.light` | 2 秒内可撤销 |
| 长按 | 卡片 | 朗读当前单词 + 一键收藏到生词本（`isFavorite = true`），弹出 2 秒 toast | `.medium` | 点 toast 取消收藏 |
| 下拉 | 卡片区顶部 | 无（避免与系统手势冲突） | — | — |

**判定细节**

- 位移阈值：水平位移 > 卡片宽 × 30%（≈105pt）且水平分量 > 垂直分量 × 1.5 才触发；未达阈值松手回弹（spring，0.28s）。
- 滑动过程中卡片跟手（`offset` 实时），动作层透明度随位移线性 0 → 1。
- 滑动结束后卡片飞向屏幕外（0.22s）再切下一张，避免「卡片跳回」。
- 已翻面时才允许左右滑评分；未翻面时左滑仅提示「先看答案」，不写记录（防止盲滑）。
- 手势与四档按钮**写同一条记录**：左滑 ≡ 不认识，右滑 ≡ 认识，`StudyRecord` 无差别。
- 可撤销：判定后 2 秒内底部出现「撤销」，撤回 `ReviewState` 与 `StudyRecord`（内存中回滚，不重复写）。

**边界**

| 情况 | 处理 |
|---|---|
| VoiceOver 开启 | 关闭滑动评分，只保留按钮（避免误判）；长按改为标准 `accessibilityAction` |
| Reduce Motion | 滑动改为淡入淡出 0.15s，无位移飞出 |
| 卡片内含可滚动内容且已到顶/底 | 纵向滚动优先，横向仍归卡片 |
| 最后一张卡滑走 | 直接进完成页，撤销入口保留在完成页顶部 2 秒 |

**四档反馈**

| 按钮 | Rating | 用户含义 | 下次间隔 |
|---|---|---|---|
| 不认识 | 1 | 完全没印象 | 1 天后 |
| 模糊 | 3 | 想起来但不熟 | 略增 |
| 认识 | 4 | 想起来了 | 正常增长 |
| 很简单 | 5 | 秒答 | 大幅增长 |

- 按钮只在背面出现；正面不提供评分（避免盲猜）。
- 点击后 0.25s 内切下一张，进度条前进，条数 `3 / 20` 更新。
- 触觉：轻 `UIImpactFeedbackGenerator(style: .light)`；「不认识」用 `.rigid`。

**完成页**

- 勾选图标 + 「今天的词过完了」
- 三连：正确率 `(good+easy)/answered`、用时、连续打卡
- 小豆一句话（`sessionDone(accuracy:streak:)`）
- 按钮：回到今日（主）/ 再复习错词（次）

**规则**

- 会话期间不写 `StudySession.endedAt` 之外的状态；每张卡的写入在 `apply(rating:)` 内一次性完成（ReviewState + StudyRecord + session 计数 + save）。
- 中断（关 App、来电、锁屏）：已评分的卡片不回退；重开今日页重新建队列，已评分词的 `dueDate` 已是明天，自然不在队列里 → **幂等**。
- 自动发音受 `settings.autoPlay` 控制；静音键打开时 `AVSpeechSynthesizer` 仍可能出声，需在设置页说明（见 §10 风险 R-06）。
- 队列为空时点「开始学习」：直接进入完成页（不显示空卡片）。

**边界**

| 情况 | 处理 |
|---|---|
| 本次会话中新词额度被设置改小 | 本次不打断，次日生效 |
| 卡片内容超长（例句 300 字） | 卡片可滚动，评分栏固定底部 |
| 会话超 30 分钟 | 不打断；统计用时照实记录 |
| 学习中断后当天再进入 | 重建队列；已完成的不重复 |

**验收**：AC-11 ~ AC-18。

### 5.4 F4 词库管理

**目的**：看清有哪些库、每个库多少词、能搜、能删。

**词库列表（P-04）**

- 每行：库名、词数、到期数、「内置」标签（`isBuiltIn`）、右箭头。
- 顶部「+」→ 菜单：**导入文件** / 新建空词库。
- 左滑：删除（二次确认，提示「同时删除该库 N 个词与学习进度」）。
- 排序：`sortIndex` 升序；内置示例库固定第一。

**词条列表（P-05）**

- 搜索框（实时，匹配 `word` / `normalized` / `meaning`），不区分大小写。
- 每行：单词、词性、释义（截断 1 行）、右侧小圆点表示学习状态（未学/学习中/已掌握）。
- 排序：默认 `sortIndex`；可切「字母序 / 添加时间 / 到期时间」。
- 左滑：收藏（进生词本）、删除单词（删 ReviewState 与记录，二次确认）。

**词条详情（P-06）**：全字段 + 学习状态（ease / 间隔 / 下次到期 / 错误次数）+ 「单独复习这个词」。

**规则**

- 删除词库：`Deck.words` 级联删 → `Word.reviewState`、`Word.records` 级联删；`StudySession` 保留（历史统计不归零，见 §7.2）。
- 重名库允许存在（不强制唯一），但导入时提示「已有同名词库」。
- 内置库可删（用户自由），删除后不自动重建；「恢复示例词库」在设置页提供。

**验收**：AC-19 ~ AC-23。

### 5.5 F5 导入与导出

**目的**：让用户把自己的词库带进来，不丢字段、不静默失败。

#### 5.5.1 CSV 契约

```csv
word,phonetic,partOfSpeech,meaning,example,exampleTranslation,tags,note
abandon,/əˈbændən/,v.,放弃；抛弃,He abandoned the plan.,他放弃了这个计划。,考研 高频,书面语偏多
```

| 列 | 必填 | 说明 | 别名（都接受） |
|---|---|---|---|
| `word` | ✅ | 单词/短语 | 单词, term, 词 |
| `phonetic` | | 音标，原样保留 | 音标, ipa |
| `partOfSpeech` | | 词性 | 词性, pos |
| `meaning` | ✅ | 释义，可含多个义项用 `;` | 释义, 中文, definition |
| `example` | | 例句 | 例句, sentence |
| `exampleTranslation` | | 例句翻译 | 例句翻译, 例句释义 |
| `tags` | | 逗号分隔，存 `tagsRaw` | 标签, tag |
| `note` | | 备注 | 备注, memo |

**解析规则**

1. 编码：优先 UTF-8（含 BOM），失败回退 GB18030；两者都失败 → 报「文件编码无法识别，请另存为 UTF-8」。
2. 换行：`\n` / `\r\n` 都接受；单元格内换行由引号包裹。
3. 引号：支持 `""` 转义；字段内逗号必须被引号包裹。
4. 表头：去空格、去 BOM、大小写不敏感；缺 `word` 或 `meaning` 列 → 直接失败并说明。
5. 空行跳过；`word` 或 `meaning` 为空的行 → 跳过并计入错误行。
6. 单词规范化：`normalized = word.trimmed.lowercased()`；同一文件内重复 → 只保留第一条，记「重复 N 条」。
7. 与库内已有词重复：默认**跳过**（可切换「覆盖」）。
8. 单次上限 20,000 行；超出提示分批导入。

**预览与错误报告（P-07）**

- 导入前显示：将导入 N 条、跳过 M 条（重复）、错误 K 条；预览前 5 条。
- 错误明细：行号 + 原因（`第 12 行：单词为空`），最多展示 20 条，可「复制全部错误」。
- 导入过程：进度条 + 可取消（已写入的保留，提示「已导入 N 条」）。

#### 5.5.2 JSON 备份契约

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-11-07T12:00:00Z",
  "appVersion": "0.1.0",
  "settings": { "dailyNewLimit": 20, "dailyReviewLimit": 100, "voiceAccent": "en-US" },
  "decks": [
    {
      "name": "示例词库", "summary": "24 个基础词", "isBuiltIn": true, "sortIndex": 0,
      "words": [
        {
          "word": "abandon", "phonetic": "/əˈbændən/", "partOfSpeech": "v.",
          "meaning": "放弃；抛弃", "example": "…", "exampleTranslation": "…",
          "tags": "考研,高频", "note": "…", "isFavorite": false,
          "reviewState": {
            "easeFactor": 2.5, "intervalDays": 3, "repetitions": 2,
            "dueDate": "2026-11-10T00:00:00Z", "lastReviewedAt": "2026-11-07T10:12:00Z",
            "lapses": 0, "phase": "review"
          }
        }
      ]
    }
  ],
  "sessions": [ { "kind": "study", "startedAt": "…", "endedAt": "…", "newWordCount": 20, "reviewCount": 0, "answeredCount": 20, "correctCount": 17 } ]
}
```

- 导出用 `fileExporter`，文件名 `豆卡单词-备份-yyyyMMdd-HHmm.json`。
- 导入（恢复）策略：**合并**（同库名合并、同词跳过/覆盖可选）或**替换全部**（二次确认，需输入「替换」）。
- 版本不匹配：`schemaVersion > 当前` → 拒绝并提示升级 App；`< 当前` → 走迁移函数。

**验收**：AC-24 ~ AC-30。

### 5.6 F6 生词本 / 错词本

**目的**：把「没记住的」集中起来，能一键再练一遍。

**两种来源**

| 类型 | 触发 | 存储 |
|---|---|---|
| 错词 | 评分 = 不认识 / 模糊（`needsReviewList`） | 派生查询：`ReviewState.lapses > 0` 或最近一次 rating ≤ 3 |
| 拼写错词 | 测试「看义拼词」答错 | 写回 `apply(rating: .again)`，自然进入上面的派生集合（见 §5.7.1） |
| 收藏 | 词条详情/列表左滑/长按卡片 | `Word.isFavorite = true` |

**界面**：今日页快捷行「错词本 · N 个」→ 错词本页（P-13）；页内可切「卡片流 / 列表」，或直接开专项会话（队列 = 错词按 `dueDate` 升序，一次最多 20 个）。

#### 5.6.3 单词本浏览 UX（F18）

**两种视图，同一份数据**

| 视图 | 用途 | 交互 |
|---|---|---|
| 卡片流（默认） | 「过一遍」——快速扫 12 个错词 | 轻点 → 下一个；左滑 → 移出错词本；右滑 → 收藏到生词本 |
| 列表 | 「找某个词」——搜索、批量整理 | 行点击 → 详情；左滑 → 移出 / 收藏；长按 → 菜单 |

**卡片流规格**

- 一屏一张卡：单词（34pt）、音标、词性胶囊、释义（22pt）、例句（12pt，最多 2 行）、底部状态行（错词 N 次 · 上次 x 月 x 日 · 下次复习）。
- 顶部计数 `3 / 12`，底部 3pt 进度条；轻点任意空白处前进，不要求精确点卡片。
- 左滑移出：写入 `wrongBookHiddenAt`，**不动记忆曲线**（词还在，只是不显示在错词本）；toast「已移出 · 撤销」。
- 右滑收藏：`isFavorite = true`，toast「已加入生词本」。
- 滑到边界时回弹并给一次轻触觉，不循环。
- 已移出的词在「已移出」筛选里可放回（清空 `wrongBookHiddenAt`）。

**列表规格**

- 搜索框（`word` / `normalized` / `meaning`）。
- 行：单词、词性 + 释义（1 行截断）、右侧「N 次」错词计数；被移出的行降到列表底部并降透明度。
- 左滑：移出 / 收藏；长按：朗读、收藏、移出错词本、查看详情（四项菜单）。
- 分段筛选：待复习 / 全部 / 已移出。

**空态**：雪球（`AnimalView(.xueqiu)`）+ 小豆一句「还没有错词，先学几个词」。

#### 5.6.4 错词判定与移出

- 判定：`isWrongWord = !isSuspended && (lapses > 0 || lastRating ∈ {again, hard})`。
- 再次判「不认识/模糊」会清空 `wrongBookHiddenAt`，自动回到错词本（用户手动移出不是永久屏蔽）。
- 「已掌握」判定：`repetitions ≥ 3 && intervalDays ≥ 21` → 从「待复习」筛选里隐藏（仍可在「全部」里看到）。

**规则**

- 错词是**派生状态**，不额外建表，避免双写不一致。
- 「已掌握」判定：`repetitions ≥ 3 && intervalDays ≥ 21`，从错词本自动移除（可在设置关掉自动移除）。
- 专项复习同样写 `StudyRecord`，但不占当日新词额度。

**验收**：AC-31 ~ AC-33。

### 5.7 F7 测试

**目的**：离开提示环境检验记忆，给用户一个「我到底记住了没」的量化感受。

**三种题型**

| 题型 | 题干 | 作答 | 选项/判定 |
|---|---|---|---|
| 看词选义 | 单词 | 4 选 1（释义） | 干扰项优先同词性、长度相近 |
| 看义拼词 | 释义 + 首字母提示 | 键盘输入 | 忽略大小写与首尾空格；完全匹配算对 |
| 听音选词 | TTS 朗读（可重播 3 次） | 4 选 1（单词） | 干扰项长度相近 |

**出题规则**

- 题池：`reviewState != nil` 的词（已学）；不足 4 个 → 提示「先学几个词再来测」。
- 每轮 10 题，题型按 4:3:3 混合；同一轮不重复出同一个词。
- 每题作答后立即反馈（对/错 + 正确项高亮 1.2s），自动下一题。
- 结果页：正确率、用时、错题列表（可一键加入错词本）。

**与 SRS 的关系**

- **选择题 / 听音题答错**：不改复习间隔，只写 `StudySession(kind: "quiz")` 的计数。理由：四选一有 25% 猜中率，用它惩罚记忆曲线不公平。
- **拼写题答错**：视为一次「主动回忆失败」，写回 `StudyRepository.apply(rating: .again, ...)`，词自动进错词本（见 §5.7.1）。理由：拼错说明真的没记住，代价应该反映在下次复习上。
- 拼写题**答对**不写回（避免一轮 10 题把间隔推太快）。

#### 5.7.1 拼写错误归错词（决策）

| 项 | 规则 |
|---|---|
| 判定 | `QuizService.isCorrect` 已做 trim + lowercase；仍不等 → 错 |
| 写回 | `apply(rating: .again)`：`lapses + 1`、`interval = 1`、`dueDate = 明天`、`phase = relearning` |
| 界面 | 输入框红边 + 「正确拼写：xxx」+ toast「已加入错词本 · 错了 N 次」 |
| 统计 | 同一次 `StudyRecord`（`wasNew = false`），不计入当日新词额度 |
| 防抖 | 同一轮同一词只写回一次（一轮不重复出题，天然成立） |

**验收**：AC-34 ~ AC-36、AC-53 ~ AC-55。

### 5.8 F8 统计

**目的**：让进步可见，但不制造焦虑。

| 模块 | 内容 | 口径 |
|---|---|---|
| 今日 | 已学 / 待复习 | 见 §7 计数口径 |
| 累计 | 学过的词数（distinct word） | `ReviewState` 数量 |
| 正确率 | 全期 `(good+easy)/answered` | 来自 `StudyRecord`，测试不计 |
| 连续打卡 | 连续有学习记录的天数 | `DayKey` 集合 |
| 7 天柱状图 | 每天「新学 + 复习」堆叠柱 | Swift Charts，`dayKey` 聚合 |
| 到期曲线 | 未来 7 天每天到期数 | `ReviewState.dueDate` 分组 |
| 掌握度 | 未学 / 学习中 / 已掌握 三段环 | `repetitions` 阈值 |

**规则**

- 无数据时显示空态插画（雪球）+「还没有记录，今天开个头」。

- 掌握度三段环（2026-11 补）：未学 / 学习中 / 已掌握 三段之和必须等于总词数；0 值段不画。
- 统计只读，不可编辑。

**验收**：AC-37 ~ AC-39、AC-81、AC-82。

### 5.10 F10 本地提醒

**目的**：在用户选的时间提醒一次，不打扰、不重复、不越权。

**规则**

- 使用 `UNCalendarNotificationTrigger(dateMatching: DateComponents(hour:minute:), repeats: true)`，identifier 固定 `daily.reminder`——重复设置时先 `removePendingNotificationRequests` 再添加，避免堆叠。
- 文案池随机（本地，不联网），示例：「今天的词还等着你」「10 分钟，把到期词清掉」。
- 权限：首次在第 3 步请求；被拒时设置页显示「通知已关闭 · 去系统设置」，点击跳 `UIApplication.openSettingsURLString`。
- 关闭开关 → 移除 pending 请求；重新打开 → 重新注册。
- 修改时间 → 移除旧的 + 注册新的。
- 不判断当天是否已完成（无法在无后台任务时可靠判断）；文案不写「你还没学」这种会打脸的句子。

**验收**：AC-43 ~ AC-45。

### 5.11 F11 小豆：文案、气泡、引导

#### 5.11.1 人设

- 身份：住在 App 里的小助手，不催、不夸、不说教。
- 唤醒语：`小豆小豆` **暂不使用**。它是语音唤醒词，等真的做语音唤醒（「小豆小豆」→ 开始今天的复习）时再用；当前所有气泡都是纯文字，念出来像自言自语，气泡上的「小豆」签名已经足够表明是谁在说话。
- 长度：主句 ≤ 22 字；副句 ≤ 20 字；最多一个感叹号，且只在完成/庆祝时用。
- 禁用：`主人`、`宝宝`、`冲鸭`、`yyds`、`绝绝子`、任何感叹号连用、任何带有责备意味的「又」「还没」。

#### 5.11.2 气泡组件

| 属性 | 取值 |
|---|---|
| 语气 `BubbleTone` | neutral / brand / success / warning / danger |

### 5.13 F16 弹幕复习（P-14）

**目的**：给「只有 1 分钟、不想做任何决定」的场景一个零操作复习方式——像电影片尾字幕一样，词自己往上走，用户只要看。

**一句话**：整屏从下往上匀速滚动；竖屏一个词占两行（单词+音标 / 词性+释义），横屏压成一行；**只有「轻点暂停/继续」和「退出」两种交互**，其余什么都不用做。支持黑、白两种主题。

**入口**：今日页快捷行「弹幕复习」；错词本顶部「过一遍」；完成后回原页面。

**界面（竖屏）**

| 区域 | 内容 |
|---|---|
| 背景 | 深色主题 `#1C1B18` / 浅色主题 `#F7F5F1`（见下「主题」） |
| 顶栏 | 左「弹幕复习」+ 副标题「48 个词 · 约 4 分钟」；右「结束」；「结束」下方是主题切换 chip |
| 滚动区（竖屏） | 每个词占 **2 行**：第 1 行 = 单词 23pt 奶油色 + 音标 12pt 灰字（同一行，整组居中）；第 2 行 = 词性 + 释义 13pt 灰字；词距 74pt |
| 滚动区（横屏·深色） | 每个词压成 **1 行**：`单词  音标  词性 释义`，15pt 奶油色，行距 54pt |
| 滚动区（横屏·浅色） | 同上，但底色 `#F7F5F1`、单词 `#1C1B18`、音标 `#A39D93`、释义 `#6E6962`；右上角主题按钮显示 `● 浅色` |
| 边缘 | 上下各 3–4 行压暗（透明度递减），模拟渐隐，避免「突然出现」 |
| 底部 | 2pt 进度条 + `3 / 48` + 「轻点屏幕暂停 · 再点继续」 |

**滚动规则**

- 恒定速度从下往上，**整屏同步位移**（不是每个词单独飘）；竖屏每 2.4 秒、横屏每 2.2 秒走过一个词，48 个词约 4 分钟。
- 词与词之间间距固定，不因长释义变化（竖屏长释义单行截断，仍保 2 行结构；横屏整行居中）。
- **音标与词性必填展示**：音标缺失时留空不占位，词性缺失时只显示释义。
- **不显示任何学习状态**：不标「错了 N 次」、不标「新词/到期」，滚动屏只做「看」这件事。
- 上下边缘的暗化是遮罩，不改变滚动本身。
- 轮到下一个词时无动画强调、无音效（安静是设计的一部分）。

**交互（只有两个）**

| 操作 | 行为 |
|---|---|
| 轻点屏幕任意处 | 暂停；再轻点继续（从原位继续，不跳回） |
| **从屏幕左缘向右滑** | 退出，回到入口页（与系统返回手势一致） |
| 点右上「结束」 | 退出，回到入口页（给不习惯手势的人兜底） |
| 暂停态下点「结束」 | 同样是退出；暂停条右侧也有「结束」，误触也不丢位置 |

- 暂停时：中间浮一条半透明条「已暂停 · 轻点任意处继续」+ 图标，**不出现任何按钮矩阵**。
- 不做长按、不做滑动调速；速度只在设置页调（0.5× / 1× / 1.5×）。
- 切后台/来电自动暂停，回前台停在原位。

**主题（黑 / 白）**

| | 深色主题（默认，跟随系统） | 浅色主题 |
|---|---|---|
| 背景 | `#1C1B18` | `#F7F5F1` |
| 单词 | 奶油 `#FFF1E8` | `textPrimary #1C1B18` |
| 音标 | 40% 白 | `textTertiary #A39D93` |
| 词性 + 释义 | 70% 白 | `textSecondary #6E6962` |
| 进度条 | brand / 20% 白 | brand / border |
| 切换 | 顶栏「◐ 深色 / ◐ 浅色」chip，一触切换，立即生效 | 同左 |

- 首次进入跟随系统外观（`colorScheme`）；用户手动切换后记住选择，不再跟随系统。
- 两套主题只换颜色，**排版、字号、行距、速度完全一致**；浅色不是「反色版」，而是按浅底重新定的层次（单词最重、音标最轻）。
- 切主题不重置滚动位置。

**退出方式（三个出口）**

| 出口 | 说明 | 优先级 |
|---|---|---|
| 左缘右滑 | 主出口，和系统返回手势一致；整屏可滑，不需要瞄准 | P0 |
| 右上「结束」 | 兜底按钮，给不习惯手势的人 | P0 |
| 暂停后「结束」 | 暂停条右侧同样有「结束」，避免误触后不知所措 | P1 |

- 退出时**记住看到哪一个词**（本地存 `creditsPosition`）；下次进来从同一个词继续，不从开头放。
- 退出**不写任何学习记录**：不评分、不改 `dueDate`、不加 `lapses`。
- 首次进入时底部浮一行「← 右滑退出」提示，3 秒后淡出；只出现一次（`hint.credits.exit.v1`）。
- 退出后回到入口页（今日页 / 错词本），不改变入口页滚动位置。

**内容池**

- 默认「全部已学词」（有 `ReviewState`）；错词优先排在前面（只影响顺序，不显示次数）。
- 顺序：错词 → 今日到期 → 其余按 `dueDate` 升序；一轮内不重复。
- 只读：**看滚动不写任何学习记录**（不评分、不改间隔）。要记录就去学习卡或错词本。
- 池子 < 4 个 → 空态：雪球 + 「先去学几个词」。

**横屏**

- 手机横过来自动切换（宽 > 高即触发），不做单独开关。
- 布局：一行一个词（`单词 音标 词性 释义`，15pt），整组水平居中；行距 54pt，一屏约 4–5 个词；底部进度条从左边 20 通到右边 824。
- 横屏速度自动 ×0.9，视觉上不显得赶。
- 竖回来自动恢复竖屏排布，位置连续。

**为什么不做「点词加错词」**

零操作是这一屏的核心价值：任何按钮都会把「无脑扫」变成「做决定」。错词收集交给学习卡与测试，这里只负责「再看一眼」。

**性能与无障碍**

- `TimelineView(.animation)` 或 `CADisplayLink` 驱动一个整体 `offset`，不为每个词单独建动画。
- 长列表用 `LazyVStack`，只渲染可视区 ±2 屏。
- VoiceOver：改为静态列表 + 「下一个」按钮；Reduce Motion：改为每 2.4 秒淡入换词。

**验收**：AC-56 ~ AC-62、AC-71 ~ AC-73。

### 5.14 F19 小豆分析推荐（InsightEngine）

**目的**：让小豆的每句话都**有数据依据、有明确动作**，并且能把「该复习的词」推进今日队列——从一个装饰性吉祥物变成产品里的「教练」。

**设计原则**

1. **无动作不说话**：每条洞察必须带一个可点的动作（跳转/加词/改设置），纯感慨的话不发。
2. **只说三件事**：到期积压、时段正确率、错词次数。不做心理揣测、不做人格评价。
3. **克制**：每天最多 3 条，同类 24 小时不重复；用户点「知道了」后 7 天内不再提同类。
4. **本地计算**：全部在设备上算，不联网、不上传、不用模型猜（与 §10 隐私一致）。

#### 5.14.1 数据信号（本地聚合）

| 信号 | 来源 | 用途 |
|---|---|---|
| `dueCount` / `overdueDays` | `ReviewState.dueDate` | 积压提醒、逾期词推荐 |
| `hourlyAccuracy[24]` | `StudyRecord.reviewedAt` + `rating` | 找「记得最牢的时段」 |
| `lapseLeaders` | `ReviewState.lapses` 降序 | 常错词推荐 |
| `recentWrong` | 最近 24h `rating ∈ {again, hard}` 或拼写错 | 刚错的词推荐 |
| `streak` / `daysSinceLastStudy` | `StudySession.dayKey` | 回归提醒、连续打卡 |
| `weeklyNew` / `weeklyMastered` | `ReviewState.repetitions` | 进度反馈 |
| `sessionSeconds` | `StudySession.startedAt/endedAt` | 推荐时长与词量 |

#### 5.14.2 规则表（按优先级，同一天只取前 3 条）

| ID | 触发条件 | 文案（≤22 字） | 动作 | 优先级 |
|---|---|---|---|---|
| N-01 | `daysSinceLastStudy ≥ 3` | 「3 天没来了，先热 5 个旧词」 | 开学习卡（只复习 5 个） | 100 |
| N-02 | `dueCount ≥ 2 × 日均学习量` | 「12 个词堆着了，今天先清一半」 | 开学习卡（只复习） | 90 |
| N-03 | 有 `lapses ≥ 3` 且未到期的词 | 「abandon 错了 3 次，今天再过一遍」 | 加入今日推荐（最多 3 个） | 80 |
| N-04 | 最近 24h 有拼写错 | 「confident 刚拼错，再写一遍」 | 加入今日推荐 | 75 |
| N-05 | 有逾期 ≥ 3 天的词 | 「5 个词逾期了，先补上」 | 错词本（筛「待复习」） | 70 |
| N-06 | `hourlyAccuracy` 样本 ≥ 20 且晚间 ≥ 早间 + 15% | 「你晚上 9 点记得最牢」 | 改提醒时间（预填 21:00） | 60 |
| N-07 | 连续 3 天未完成新词额度 | 「新词定多了？改成 10 个试试」 | 设置（每日新词） | 50 |
| N-08 | 本周 mastered ≥ 5 | 「这周拿下 8 个词」 | 看统计 | 40 |
| N-09 | 今日任务已清空 | 「今天清完了，明天见」 | 无动作（唯一允许的纯提示） | 10 |

- 同一词 7 天内不进两次推荐。
- N-06 需要 ≥ 20 条记录才触发，避免小样本胡说。
- 全部规则纯函数：`InsightEngine.evaluate(snapshot:) -> [Insight]`，可单测。

#### 5.14.3 推荐进今日计划

**今日队列 = 到期复习 + 新词 + 小豆推荐（≤3）**

| 段 | 来源 | 上限 | 标记 |
|---|---|---|---|
| 到期复习 | `dueDate ≤ 今日` | `dailyReviewLimit` | 无 |
| 新词 | `reviewState == nil` | `dailyNewLimit` | 无 |
| 小豆推荐 | 错得最多 / 逾期最久 / 刚拼错 | 3 | 卡片顶部橙色 chip「小豆推荐 · 错了 3 次」 |

- 推荐词**不占新词额度**，但也不算新词（`wasNew = false`）。
- 推荐词学完后回正常 SRS，`dueDate` 按评分重算。
- 今日页任务卡显示 `+3 小豆推荐` 小标签，点开可看「为什么推荐」列表（词 + 原因 + 加入/忽略）。
- 推荐词若已在当日队列（到期或新词），不重复添加。

#### 5.14.4 展示位置与联动

| 位置 | 条数 | 动作落点 |
|---|---|---|
| 今日页小豆卡（顶部，替代普通鼓励语） | 1（最高优先级） | 直接执行：开学习卡 / 加推荐 / 改提醒 |
| 学习完成页 | 1 | 「明天 14 个到期」→ 回今日 |
| 错词本顶部 | 1 | 「过一遍这 12 个」→ 弹幕复习 |
| 设置 → 小豆分析 | 全部 | 洞察面板（时段柱图 + 常错 Top3 + 规则说明） |

- 每条洞察有 `dismiss`（知道了）与 `action`（去做）；dismiss 记冷却。
- 小豆文案与 `XiaodouMoment` 共用语气规范（≤22 字、最多一个感叹号、不叫「主人」）。

#### 5.14.5 边界与隐私

| 情况 | 处理 |
|---|---|
| 新用户（< 10 条记录） | 只出 N-01/N-09 这类不需要统计的，或干脆不说话 |
| 数据被重置 | 洞察状态一并清空 |
| 用户连续 dismiss 3 次 | 7 天内不再主动弹，只在设置里可查 |
| 隐私 | 所有聚合在本地完成；导出备份里**不含**洞察历史 |

**验收**：AC-65 ~ AC-70。

## 6. 复习算法规格

### 6.1 数据结构

```
ReviewState {
  easeFactor: Double = 2.5      // 1.3 … 3.0
  intervalDays: Int = 0         // 0 … 365
  repetitions: Int = 0
  dueDate: Date
  lastReviewedAt: Date?
  lapses: Int = 0
  phase: .new | .learning | .review | .relearning
  isSuspended: Bool = false
}
```

### 6.2 评分映射

| 按钮 | Rating | 语义 |
|---|---|---|
| 不认识 | 1 | 完全失败 |
| 模糊 | 3 | 勉强想起 |
| 认识 | 4 | 正常想起 |
| 很简单 | 5 | 瞬时反应 |

### 6.3 规则表

记 `e` = easeFactor，`i` = intervalDays。

| 评分 | repetitions | intervalDays | easeFactor | lapses | phase |
|---|---|---|---|---|---|
| Again (1) | → 0 | → 1 | `max(1.3, e - 0.20)` | +1 | relearning |
| Hard (3) | +1 | `i=0→1`；`i=1→2`；否则 `max(i+1, round(i×1.2))` | `max(1.3, e - 0.15)` | 不变 | review |
| Good (4) | +1 | `i=0→1`；`i=1→3`；否则 `round(i×e)` | 不变 | 不变 | review |
| Easy (5) | +1 | `i=0→4`；`i=1→7`；否则 `round(i×e×1.3)` | `min(3.0, e + 0.15)` | 不变 | review |

**统一收尾**

- `intervalDays = clamp(interval, 1, 365)`
- `dueDate = startOfDay(now) + intervalDays 天`（用 `Calendar`，**禁止**用 86400 秒硬算）
- `lastReviewedAt = now`
- 所有函数纯函数化：`SRSAlgorithm.schedule(easeFactor:intervalDays:repetitions:lapses:rating:now:calendar:) -> SRSOutcome`

### 6.4 示例轨迹（一次「认识」到底）

| 次 | 评分 | 间隔 | 累计天数 | ease |
|---|---|---|---|---|
| 1 | 认识 | 1 | D1 | 2.5 |
| 2 | 认识 | 3 | D4 | 2.5 |
| 3 | 认识 | 8 | D12 | 2.5 |
| 4 | 认识 | 20 | D32 | 2.5 |
| 5 | 模糊 | 24（max(21, 24)） | D56 | 2.35 |
| 6 | 很清楚 | 56（round(24×2.35) → 56） | D112 | 2.5 |

> 若第 4 次选「不认识」：间隔回到 1 天，ease 2.3，lapses=1，phase=relearning。

### 6.5 队列生成

```swift
// 1) 到期复习：dueDate <= 今日 00:00 且未挂起
//    排序：dueDate 升序，同日期按 lapses 降序（错得多的先来）
reviewQueue = states
    .filter { !$0.isSuspended && $0.dueDate <= startOfToday }
    .sorted { ($0.dueDate, -$0.lapses) < ($1.dueDate, -$1.lapses) }

// 2) 新词：没有 ReviewState 的词，按 sortIndex
newQueue = words
    .filter { $0.reviewState == nil }
    .sorted { $0.sortIndex < $1.sortIndex }

// 3) 按「限额 − 今日已用」截断
reviewLimit = max(0, settings.dailyReviewLimit - reviewedToday)
newLimit    = max(0, settings.dailyNewLimit    - learnedNewToday)

queue = reviewQueue.prefix(reviewLimit).map { Item($0, isNew: false) }
      + newQueue.prefix(newLimit).map { Item($0, isNew: true) }
```

**计数口径**

| 名称 | 定义 |
|---|---|
| `due` | 到期且未挂起的 ReviewState 数（不按额度截断，今日页显示真实缺口） |
| `new` | 当前库中 `reviewState == nil` 的词数（同上，不截断） |
| `learnedToday` | 今天 `StudyRecord.wasNew == true` 的 **distinct** 词数 |
| `reviewedToday` | 今天 `StudyRecord.wasNew == false` 的 distinct 词数 |

### 6.6 为什么不用 FSRS（决策记录）

- FSRS 需要 3 个以上参数、单条记忆的稳定性/难度建模，输入只有四档评分时收益有限；
- 纯函数、可解释、可单测优先，SM-2 的四档变体已足够覆盖 90% 场景；
- 未来若引入，`SRSAlgorithm` 是纯函数，替换成本低，`ReviewState` 预留 `phase` 与 `lapses` 可扩展。
